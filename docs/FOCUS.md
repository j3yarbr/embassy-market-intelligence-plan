# Focus

**Status:** ✅ Live · **Last updated:** 2026-08-27
**Live URL:** https://j3yarbr.github.io/embassy-market-intelligence-plan/focus/

Part of the Embassy Market Intelligence Suite (see `README.md`). Focus is the Prospect Finder Map — it isolates local organizations across the four-state territory ready for custom branded apparel and hardgoods, so a rep can see where the real opportunity is instead of driving blind or cold-calling waste.

## What it is

An interactive Folium/Leaflet map plotting existing clients (blue) and untapped prospects (red), clustered, with a category filter panel. Generated by `market_intelligence_engine.py`, a PyInstaller-compiled Windows tool a rep runs locally — source lives at:

```
My Drive\Embassy Market Intelligence\Phase 1 Market Intelligence - Focus\Market Gap Map Application\
```

## How a run works

1. **Loads existing clients** from a Sage CRM export CSV, pulled from a network share:
   `\\server-1\shared\Market Intelligence Hub - Matt Yarbrough\Current Sage Client List with Valid Address\Client List in Sage with Geocode Match.csv` (the mapped `S:\` drive letter works from a normal shell; the raw UNC path does not).
2. **Pulls prospects** from OpenStreetMap via the Overpass API, cached at `%LOCALAPPDATA%\EmbassyIntel\prospect_cache.csv`, bounded to a 7-point polygon anchored on real towns in drive order: Wichita → Kansas City → Sedalia → Springfield → Branson → Fort Smith → Tulsa. This replaced a full four-state pull that reached irrelevant places (Little Rock, OKC, St. Louis) and cut prospect count from 123,632 to 26,859.
3. **Buckets every prospect** into a Sage-CRM-style industry category (Banking, Legal, Salon & Spa, Automotive, etc.) via `categorize_prospect()`, mapping raw OSM tags through hand-built lookup tables, defaulting unmapped tags to "Other" rather than dropping them.
4. **Writes the map** (`index.html`, Folium/Leaflet) plus the plotted points (`data.json`) and `cluster_callback.js` to `C:\Users\Owner\Desktop\Embassy Market Intelligence\` (the app's own output folder — separate from the Drive source and unaffected by the Drive migration).
5. Those three files get copied into this repo's `site/focus/` and pushed to deploy.

## Key design decisions worth knowing before touching this

- **Data loads via `fetch("data.json")` at runtime, not embedded in the HTML.** An earlier version embedded all data directly in the page, which worked on desktop but was too large for mobile Safari. The tradeoff: `fetch()` requires the page be *served* (http/https) — it silently fails under browser CORS restrictions if `index.html` is opened directly as a local file (`file://`). **Always test via a served URL** (a local static server, or the live Pages URL), never by double-clicking the file. This was the root cause behind "weeks" of the map appearing broken before it was diagnosed.
- **Markers are added in bulk (`addLayers()`), never one at a time (`addTo()`) in a loop.** Leaflet.markercluster rebuilds its spatial index on every individual insert, which froze the tab for a long time at this data's scale (~28k points, worse on iPad) — bulk loading avoids that entirely.
- **The category filter hides markers, it never discards data.** Rather than narrowing the Overpass query by industry (risky — small-town OSM tagging is too inconsistent to filter reliably at the query level), every prospect is pulled and categorized, and the checkbox panel toggles visibility per category via bulk `addLayers()`/`removeLayers()`. Nothing is thrown away upstream.
- **`cluster_callback.js` is bundled into the PyInstaller exe** (`--add-data`) and read from `sys._MEIPASS` (PyInstaller's runtime extraction dir) when frozen, `BASE_DIR` otherwise — an earlier version only found it next to the exe if manually copied.
- **Clear the prospect cache whenever the Overpass query changes.** `fetch_prospects()` silently returns the cache if it has >1000 rows, so a query edit does nothing until `%LOCALAPPDATA%\EmbassyIntel\prospect_cache.csv` is deleted. Easy to forget, produces a very confusing "I changed the query but nothing changed" symptom.

## Build

```
& "C:\Users\Owner\anaconda3\Scripts\pyinstaller.exe" market_intelligence_engine.py --onefile --noconsole --icon=logo.ico --add-data "splash.png;." --add-data "cluster_callback.js;." --add-data "C:\Users\Owner\anaconda3\Lib\site-packages\folium\templates;folium\templates" --exclude-module scipy --exclude-module matplotlib --exclude-module sklearn --exclude-module PyQt5 --exclude-module PySide2 --exclude-module OpenGL --exclude-module vispy --exclude-module glfw --hidden-import pandas.plotting --hidden-import pandas._libs.tslibs --hidden-import pandas._libs.missing --hidden-import pandas._libs.hashtable --hidden-import pandas._libs.interval
```

Run from inside `Market Gap Map Application\`. Takes ~10-14 minutes (Anaconda's dependency tree pulls in jupyter/statsmodels/plotly transitively despite the exclusions). Anaconda's python/pyinstaller aren't on PATH by default in a fresh shell — use the full path above, or `C:\Users\Owner\anaconda3\python.exe`.

Clear `dist/`, `build/`, and the `.spec` file before a rebuild (Matt's own habit).

## Known gap: favicon, icons, and auto-update banner don't survive a rebuild

`market_intelligence_engine.py` doesn't write the HTML `<head>`/`<body>` directly — Folium generates it from its own template. That means the deployed `site/focus/index.html`'s manually-added favicon `<link>` tag, the `favicon.ico`/`apple-touch-icon`/`manifest.json` lines (added 2026-08-27 for the desktop/iPad home-screen icon fix — see `TECHNICAL.md`), the auto-update banner `<script>` block, and the floating "← Suite" back button **all get wiped on every rebuild**. Re-add all of these by hand after each redeploy until the Python script gets a post-processing step to reinject them (tracked in `BACKLOG.md`, not built yet).
